# Contributing to BlissLabs projects

Thanks for helping. Two documents apply to every contribution:

1. [Code of Conduct](CODE_OF_CONDUCT.md)
2. [Contributor License Agreement](CLA.md)

We will not merge original work until the CLA check is green. If you contribute
as an employee, your company must also send the Corporate CLA to
**contact@blisslabs.org**.

## Talk to us first

* Matrix: [#blissos:matrix.org](https://matrix.to/#/#blissos:matrix.org)
* Development Telegram: [t.me/androidgenericpc](https://t.me/androidgenericpc)

Say what you want to work on and what hardware you have. Pick one repository.
Do not open a huge unsolicited refactor.

Application-layer work (Boringdroid, Smart Dock, XTMapper) is listed on the
[project map](https://blissos.org/projects.html#apps). Those repos are a better
first patch than a platform tree if you write Android apps.

## How to send work

1. Read the Code of Conduct and the CLA.
2. Confirm the branch with developers (these trees move).
3. Keep git authorship honest. Do not strip credit from AOSP, Lineage, Mesa,
   Calamares, or other upstreams.
4. Open a pull request (or use Gerrit if that repo's README says to).
5. When the CLA bot comments, reply with:

   ```text
   I have read the CLA Document and I hereby sign the CLA
   ```

6. If the work is not yours, mark it as a third-party submission per the CLA.
   Do not mix it into an unsigned original patch.

## Company contributions

Signing as your personal GitHub user is not enough when the patch was written
on company time or using company IP. File the Corporate CLA, list the GitHub
usernames that are allowed to contribute, and keep that list current.

Product use of Gapps, Native Bridge, Widevine, or other proprietary public
images is a [licensing](https://blissos.org/licensing.html) matter, not a CLA
workaround.
